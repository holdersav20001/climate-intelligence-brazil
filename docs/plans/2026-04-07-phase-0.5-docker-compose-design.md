# Phase 0.5 — Docker Compose (Local) Design
**Date:** 2026-04-07
**Status:** Approved
**Scope:** Local only — `docker compose up` on development machine. No Hetzner, no CI/CD, no SSL.

---

## Goal

Unify the entire Climate Intelligence Platform into a single `docker compose up` command. Currently Paperclip runs on WSL Ubuntu and PostgreSQL runs as a standalone Docker container. Phase 0.5 brings all six services into one Docker Compose stack running locally.

---

## What Is and Is Not In Scope

### In scope
- `docker-compose.yml` — all 6 services
- `docker-compose.override.yml` — local dev overrides (expose postgres port)

- nginx SSL / certbot
- Hetzner VM provisioning
- GitHub Actions CI/CD
- Full FastAPI implementation (Phase 1)
- Full React implementation (Phase 3)
- Full BullMQ job definitions (Phase 2)
- Hermes activation (Phase 2)

## Architecture

### Six services, one `docker compose up`

| Service | Image | Role in Phase 0.5 |
|---|---|---|
| `postgres` | pgvector/pgvector:pg16 | Runs schema + seed on first start. Two schemas inside. |
| `redis` | redis:7-alpine | Ready for pub/sub and job queue. |
| `paperclip` | Built from paperclipai/paperclip Dockerfile | Paperclip dashboard + agent orchestrator + Claude Code CLI |
| `api` | ./api/Dockerfile | Stub — `/health` returns `{"status":"ok"}` |
| `frontend` | ./frontend/Dockerfile | Stub — nginx serves holding page |
| `worker` | ./worker/Dockerfile | Stub — BullMQ connects, no jobs queued |

### Startup order (healthcheck-enforced)

```
postgres (pg_isready) ─┐
                        ├─→ paperclip
redis (redis-cli ping) ─┤
                        ├─→ api
                        ├─→ worker
                        └─→ (api healthy) → frontend
```

## Database Design

### One PostgreSQL container, two schemas

```
postgres container  (pgvector/pgvector:pg16)
  └── database: climate_intel
        ├── schema: public    ← Paperclip's internal tables (agents, tasks, heartbeats)
        └── schema: climate   ← Our 25 tables (articles, findings, contacts, sources...)
```

Paperclip uses the `public` schema by default — no configuration change required on Paperclip's side.

### Two environment variables

| Variable | Value | Used by |
|---|---|---|
| `DATABASE_URL` | `postgresql://...@postgres:5432/climate_intel` | Paperclip server (public schema) |
| `CLIMATE_DATABASE_URL` | `postgresql://...@postgres:5432/climate_intel?options=-csearch_path%3Dclimate` | `db.py`, `api`, `worker` |

### PostgreSQL init sequence (docker-entrypoint-initdb.d)

1. `00_init.sh` — enables pgvector extension, creates `climate` schema
2. `01_schema.sql` — creates all 25 tables under `climate` schema
3. `02_seed.sql` — seeds tags taxonomy, countries, 38 sources

### Schema summary (25 tables under `climate` schema)

**Time-series (partitioned by month):** `articles`, `findings`, `ngo_intel`, `finance_deals`, `reports`, `run_log`

**Reference (permanent):** `sources`, `tags`, `countries`, `contacts`, `policies`, `tenants`, `alert_hashes`, `seen_urls`

**Junction:** `article_countries`, `article_tags`, `contact_countries`, `contact_tags`, `finding_countries`, `finding_tags`

**Cross-reference:** `finding_articles`, `finding_contacts`

**Tenant-specific:** `contact_access`, `tenant_filters`, `tenant_article_status`

## Paperclip Container

Paperclip is open-source and self-hosted (github.com/paperclipai/paperclip). Its official Dockerfile is used directly — no custom Dockerfile required.

Key facts about the official Paperclip container:
- Base: `node:lts-trixie-slim`
- **Claude Code CLI pre-installed** (`@anthropic-ai/claude-code@latest`) — this is how agents execute
- Runs at port 3100 (dashboard + API)
- Requires `BETTER_AUTH_SECRET` for its auth system
- Uses `DATABASE_URL` for its internal data (public schema)
- Volume at `/paperclip` persists workspace across restarts

Agent instruction files (`./agents/`) are mounted into the container. `ANTHROPIC_API_KEY` is injected from `.env`.

The `paperclip` container gets both database env vars:
- `DATABASE_URL` → Paperclip's own orchestration data
- `CLIMATE_DATABASE_URL` → available to agents when they call `db.py`

## `db.py` Update

Single targeted change — database backend swap:

```python
# Before (SQLite)
import sqlite3
conn = sqlite3.connect("intelligence.db")

# After (PostgreSQL)
import psycopg2, os
conn = psycopg2.connect(os.environ["CLIMATE_DATABASE_URL"])
# SET search_path TO climate applied on each connection
```

The CLI interface is unchanged — all 14 agent instruction files require zero edits:

```bash
python3 db.py insert-article '{"url":"...","title":"..."}'
python3 db.py insert-finding '{"agent":"...","priority":"HIGH","title":"..."}'
python3 db.py is-url-seen "https://..."
python3 db.py stats
```

## Success Criteria

Phase 0.5 is complete when:

```
✅ postgres    healthy — pg_isready passes, climate schema exists, seed data loaded
✅ redis       healthy — redis-cli ping passes
✅ paperclip   running — http://localhost:3100 loads dashboard, agents visible
✅ api         running — GET http://localhost:8000/health returns {"status":"ok"}
✅ frontend    running — GET http://localhost:80 returns holding page
✅ worker      running — starts and stays running without crash
```

Smoke test — trigger one agent heartbeat from Paperclip dashboard, then verify:

```bash
docker exec postgres psql -U climate_intel -d climate_intel \
  -c "SELECT * FROM climate.run_log LIMIT 1"
```

A row should appear confirming the agent wrote to our PostgreSQL via `db.py`.
