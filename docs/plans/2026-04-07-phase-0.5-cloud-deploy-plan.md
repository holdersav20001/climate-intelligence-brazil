### Step 1 — Create the production nginx config (10 min)

Create `nginx/conf.d/production.conf`:

```nginx
# nginx/conf.d/production.conf
# Production: SSL termination, API proxy, WebSocket proxy
# Replace DOMAIN_PLACEHOLDER with your actual domain before deploying.

server {
    listen 80;
    server_name DOMAIN_PLACEHOLDER;

    # Let's Encrypt ACME challenge — must work before cert exists
    location /.well-known/acme-challenge/ {
        root /var/www/certbot;
    }

    # Redirect all other HTTP traffic to HTTPS
    location / {
        return 301 https://$host$request_uri;
    }
}

server {
    listen 443 ssl;
    server_name DOMAIN_PLACEHOLDER;

    # SSL — managed by certbot; paths match certbot_certs Docker volume
    ssl_certificate     /etc/letsencrypt/live/DOMAIN_PLACEHOLDER/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/DOMAIN_PLACEHOLDER/privkey.pem;

    # Modern TLS settings
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_prefer_server_ciphers off;
    ssl_session_cache shared:SSL:10m;
    ssl_session_timeout 1d;

    # HSTS (enable after confirming SSL works)
    # add_header Strict-Transport-Security "max-age=63072000" always;

    # Security headers
    add_header X-Frame-Options DENY;
    add_header X-Content-Type-Options nosniff;
    add_header Referrer-Policy strict-origin-when-cross-origin;

    # --- API proxy: /api/* → FastAPI on port 8000 ---
    location /api/ {
        proxy_pass         http://api:8000/;
        proxy_http_version 1.1;
        proxy_set_header   Host $host;
        proxy_set_header   X-Real-IP $remote_addr;
        proxy_set_header   X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header   X-Forwarded-Proto $scheme;
        proxy_read_timeout 120s;
        proxy_connect_timeout 10s;
    }

    # --- WebSocket proxy: /ws/* → FastAPI WebSocket ---
    location /ws/ {
        proxy_pass         http://api:8000/ws/;
        proxy_http_version 1.1;
        proxy_set_header   Upgrade $http_upgrade;
        proxy_set_header   Connection "upgrade";
        proxy_set_header   Host $host;
        proxy_set_header   X-Real-IP $remote_addr;
        proxy_read_timeout 3600s;
    }

    # --- Frontend: everything else → React nginx on port 3000 ---
    location / {
        proxy_pass         http://frontend:3000/;
        proxy_http_version 1.1;
        proxy_set_header   Host $host;
        proxy_set_header   X-Real-IP $remote_addr;
        proxy_set_header   X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header   X-Forwarded-Proto $scheme;

        # React Router — fallback to index.html for client-side routing
        proxy_intercept_errors on;
        error_page 404 = @fallback;
    }

    location @fallback {
        proxy_pass http://frontend:3000/;
    }
}
```

**Why this structure:** The frontend container's nginx serves the React SPA on port 3000 (internal only). The outer nginx (this config) handles port 443 externally and proxies inbound traffic. This means SSL is fully terminated at the edge; the frontend container never sees TLS.

### Step 4 — Create the certbot initialisation script (10 min)

Create `scripts/certbot-init.sh`. This script runs once on the VM to issue the first certificate. It uses the webroot method so nginx stays up during issuance.

```bash
#!/usr/bin/env bash
# scripts/certbot-init.sh
# Run ONCE on the Hetzner VM after DNS is live and nginx is serving HTTP.
# Usage: ./scripts/certbot-init.sh your-domain.com your@email.com
#
# Prerequisites:
#   - docker and docker compose installed on VM
#   - DNS A record for DOMAIN pointing to this VM's IP
#   - `docker compose up -d` already running (so nginx serves port 80)

set -euo pipefail

DOMAIN="${1:?Usage: $0 <domain> <email>}"
EMAIL="${2:?Usage: $0 <domain> <email>}"

echo "==> Issuing Let's Encrypt certificate for ${DOMAIN}"
echo "    Using webroot at /var/www/certbot (served by nginx container)"

docker run --rm \
  -v certbot_certs:/etc/letsencrypt \
  -v certbot_webroot:/var/www/certbot \
  certbot/certbot certonly \
    --webroot \
    --webroot-path /var/www/certbot \
    --email "${EMAIL}" \
    --agree-tos \
    --no-eff-email \
    -d "${DOMAIN}"

echo "==> Certificate issued. Reloading nginx..."
docker compose exec frontend nginx -s reload

echo "==> Done. Certificate valid for 90 days. Auto-renewal is configured via cron."
echo "    Verify: https://${DOMAIN}"
```

Make it executable in Git:

```bash
chmod +x scripts/certbot-init.sh
git update-index --chmod=+x scripts/certbot-init.sh
```

### Step 5 — Create the certbot renewal script (5 min)

Create `scripts/certbot-renew.sh`. This is called by cron on the VM every 12 hours:

```bash
#!/usr/bin/env bash
# scripts/certbot-renew.sh
# Called by cron on the Hetzner VM to renew Let's Encrypt certificates.
# Certbot only renews when cert is <30 days from expiry — safe to run frequently.
#
# Add to crontab: 0 */12 * * * /home/ubuntu/climate-intelligence-brazil/scripts/certbot-renew.sh

set -euo pipefail

REPO_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"

echo "==> [$(date -u)] certbot renew started"

docker run --rm \
  -v certbot_certs:/etc/letsencrypt \
  -v certbot_webroot:/var/www/certbot \
  certbot/certbot renew --quiet

echo "==> Reloading nginx..."
cd "${REPO_DIR}" && docker compose exec frontend nginx -s reload

echo "==> [$(date -u)] certbot renew complete"
```

Make it executable:

```bash

git update-index --chmod=+x scripts/certbot-renew.sh
```

### Step 3 — Create the VM bootstrap script (15 min)

Create `scripts/vm-bootstrap.sh`. Run this once on a fresh Ubuntu 24.04 VM:

```bash
#!/usr/bin/env bash
# scripts/vm-bootstrap.sh
# Run ONCE on a fresh Hetzner CX32 Ubuntu 24.04 VM.
# Usage: bash vm-bootstrap.sh
# Must be run as root or with sudo.

set -euo pipefail

echo "==> [1/6] System update"
apt-get update -qq && apt-get upgrade -y -qq

echo "==> [2/6] Install Docker"
# Official Docker install script — installs CE + Compose plugin
curl -fsSL https://get.docker.com | sh

# Add the ubuntu user to the docker group (no sudo needed for docker commands)
usermod -aG docker ubuntu

echo "==> [3/6] Configure UFW firewall"
ufw --force reset
ufw default deny incoming
ufw default allow outgoing
ufw allow 22/tcp    comment 'SSH'
ufw allow 80/tcp    comment 'HTTP (redirect to HTTPS)'
ufw allow 443/tcp   comment 'HTTPS'
ufw --force enable

echo "==> [4/6] Harden SSH"
# Disable password auth — key-only access
sed -i 's/^#PasswordAuthentication yes/PasswordAuthentication no/' /etc/ssh/sshd_config
sed -i 's/^PasswordAuthentication yes/PasswordAuthentication no/' /etc/ssh/sshd_config
systemctl reload ssh

echo "==> [5/6] Install useful tools"
apt-get install -y -qq git curl jq htop

echo "==> [6/6] Bootstrap complete"
echo "    Docker version: $(docker --version)"
echo "    Compose version: $(docker compose version)"
echo "    Firewall status:"
ufw status verbose
echo ""
echo "IMPORTANT: Log out and back in (or run 'newgrp docker') before running docker commands as ubuntu."
```

Make it executable and commit it:

```bash
chmod +x scripts/vm-bootstrap.sh
git update-index --chmod=+x scripts/vm-bootstrap.sh
```

This override file tells Docker Compose to use GHCR images instead of building locally. On the VM, CI/CD uses:

Create `docker-compose.prod.yml`:

```yaml
# docker-compose.prod.yml
# Production override: use pre-built GHCR images instead of building locally.
# Used by GitHub Actions deploy step on the Hetzner VM.
```

The `IMAGE_TAG` environment variable is set by the CI/CD pipeline to the git commit SHA.

### Step 3 — Create the GitHub Actions workflow (20 min)

Create `.github/workflows/deploy.yml`:

```yaml
# .github/workflows/deploy.yml
# Climate Intelligence Platform — CI/CD pipeline
#
# Triggers: push to main branch
# Steps:
#   1. Build all 4 custom Docker images
#   2. Push to GitHub Container Registry (GHCR) with commit SHA tag
#   3. SSH to Hetzner VM
#   4. Pull new images and restart services (rolling, zero-downtime)
#   5. Notify on failure

name: Build and Deploy

on:
  push:
    branches:
      - main
  workflow_dispatch:  # Allow manual trigger from GitHub UI

env:
  REGISTRY: ghcr.io
  REPO: holdersav20001/climate-intelligence-brazil

jobs:
  # ─── Job 1: Build and push all images ────────────────────────────────────────
  build:
    name: Build & Push Images
    runs-on: ubuntu-latest
    permissions:
      contents: read
      packages: write

    outputs:
      image_tag: ${{ steps.meta.outputs.sha_short }}

    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Set image tag (short SHA)
        id: meta
        run: echo "sha_short=$(git rev-parse --short HEAD)" >> "$GITHUB_OUTPUT"

      - name: Log in to GHCR
        uses: docker/login-action@v3
        with:
          registry: ${{ env.REGISTRY }}
          username: ${{ github.actor }}
          password: ${{ secrets.GHCR_TOKEN }}

      - name: Set up Docker Buildx
        uses: docker/setup-buildx-action@v3

      # ─── paperclip ─────────────────────────────────────────────────────────
      - name: Build and push paperclip
        uses: docker/build-push-action@v5
        with:
          context: ./paperclip
          push: true
          tags: |
            ${{ env.REGISTRY }}/${{ env.REPO }}/paperclip:${{ steps.meta.outputs.sha_short }}
            ${{ env.REGISTRY }}/${{ env.REPO }}/paperclip:latest
          cache-from: type=gha,scope=paperclip
          cache-to: type=gha,mode=max,scope=paperclip

      # ─── api ───────────────────────────────────────────────────────────────
      - name: Build and push api
        uses: docker/build-push-action@v5
        with:
          context: ./api
          push: true
          tags: |
            ${{ env.REGISTRY }}/${{ env.REPO }}/api:${{ steps.meta.outputs.sha_short }}
            ${{ env.REGISTRY }}/${{ env.REPO }}/api:latest
          cache-from: type=gha,scope=api
          cache-to: type=gha,mode=max,scope=api

      # ─── frontend ──────────────────────────────────────────────────────────
      - name: Build and push frontend
        uses: docker/build-push-action@v5
        with:
          context: ./frontend
          push: true
          tags: |
            ${{ env.REGISTRY }}/${{ env.REPO }}/frontend:${{ steps.meta.outputs.sha_short }}
            ${{ env.REGISTRY }}/${{ env.REPO }}/frontend:latest
          cache-from: type=gha,scope=frontend
          cache-to: type=gha,mode=max,scope=frontend

      # ─── worker ────────────────────────────────────────────────────────────
      - name: Build and push worker
        uses: docker/build-push-action@v5
        with:
          context: ./worker
          push: true
          tags: |
            ${{ env.REGISTRY }}/${{ env.REPO }}/worker:${{ steps.meta.outputs.sha_short }}
            ${{ env.REGISTRY }}/${{ env.REPO }}/worker:latest
          cache-from: type=gha,scope=worker
          cache-to: type=gha,mode=max,scope=worker

  # ─── Job 2: Deploy to Hetzner VM ─────────────────────────────────────────────
  deploy:
    name: Deploy to Hetzner
    runs-on: ubuntu-latest
    needs: build
    environment: production

    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Deploy via SSH
        uses: appleboy/ssh-action@v1.0.3
        with:
          host: ${{ secrets.HETZNER_HOST }}
          username: ${{ secrets.HETZNER_USER }}
          key: ${{ secrets.HETZNER_SSH_KEY }}
          script: |
            set -euo pipefail

            cd /home/ubuntu/climate-intelligence-brazil

            echo "==> Pulling latest code"
            git fetch origin main
            git reset --hard origin/main

            echo "==> Setting IMAGE_TAG"
            export IMAGE_TAG="${{ needs.build.outputs.image_tag }}"
            echo "IMAGE_TAG=${IMAGE_TAG}" >> .env.deploy
            # Note: we use a separate file to avoid overwriting production .env

            echo "==> Logging in to GHCR"
            echo "${{ secrets.GHCR_TOKEN }}" | docker login ghcr.io -u ${{ github.actor }} --password-stdin

            echo "==> Pulling new images (IMAGE_TAG=${IMAGE_TAG})"
            IMAGE_TAG="${IMAGE_TAG}" docker compose \
              -f docker-compose.yml \
              -f docker-compose.prod.yml \
              pull

            echo "==> Rolling restart — stateless services first"
            # Restart worker and api first (stateless, no user-visible impact)
            IMAGE_TAG="${IMAGE_TAG}" docker compose \
              -f docker-compose.yml \
              -f docker-compose.prod.yml \
              up -d --no-deps worker api

            # Wait for api to become healthy before updating frontend
            echo "==> Waiting for API health check..."
            for i in {1..12}; do
              if curl -sf http://localhost:8000/health > /dev/null; then
                echo "    API healthy after $((i * 5))s"
                break
              fi
              echo "    Waiting... (attempt $i/12)"
              sleep 5
            done

            echo "==> Updating frontend"
            IMAGE_TAG="${IMAGE_TAG}" docker compose \
              -f docker-compose.yml \
              -f docker-compose.prod.yml \
              up -d --no-deps frontend

            echo "==> Updating paperclip"
            IMAGE_TAG="${IMAGE_TAG}" docker compose \
              -f docker-compose.yml \
              -f docker-compose.prod.yml \
              up -d --no-deps paperclip

            echo "==> Pruning old images"
            docker image prune -f --filter "until=24h"

            echo "==> Deployment complete. Running containers:"
            docker compose ps

      - name: Verify deployment
        uses: appleboy/ssh-action@v1.0.3
        with:
          host: ${{ secrets.HETZNER_HOST }}
          username: ${{ secrets.HETZNER_USER }}
          key: ${{ secrets.HETZNER_SSH_KEY }}
          script: |
            # Quick smoke test — API health endpoint must return 200
            HTTP_STATUS=$(curl -s -o /dev/null -w "%{http_code}" http://localhost:8000/health)
            if [ "${HTTP_STATUS}" != "200" ]; then
              echo "FAIL: API health check returned ${HTTP_STATUS}"
              exit 1
            fi
            echo "PASS: API health check returned 200"

      - name: Notify on failure
        if: failure()
        uses: actions/github-script@v7
        with:
          script: |
            github.rest.issues.create({
              owner: context.repo.owner,
              repo: context.repo.repo,
              title: `Deploy failed — ${context.sha.substring(0, 7)} (${new Date().toISOString().split('T')[0]})`,
              body: [
                '## Deploy Failure',
                '',
                `**Commit:** ${context.sha}`,
                `**Branch:** ${context.ref}`,
                `**Workflow run:** https://github.com/${context.repo.owner}/${context.repo.repo}/actions/runs/${context.runId}`,
                '',
                '### Next steps',
                '1. Check the workflow run logs linked above.',
                '2. SSH to the Hetzner VM and run `docker compose ps` to check container status.',
                '3. Run `docker compose logs --tail=50 <service>` for the failing service.',
                '4. If the VM is unreachable, check Hetzner console at cloud.hetzner.com.',
              ].join('\n'),
              labels: ['deploy-failure', 'urgent'],
            })
```

## Troubleshooting

| Symptom | Likely cause | Resolution |
|---|---|---|
| `certbot-init.sh` fails: "Domain not resolving" | DNS propagation not complete | Wait 5 minutes. Run `dig +short climateintel.example.com` until VM IP appears. |
| `certbot-init.sh` fails: "Connection refused on port 80" | nginx container not running | Run `docker compose ps` — if frontend is down, check logs: `docker compose logs frontend` |
| `docker compose up` fails: "port 80 already in use" | Another nginx/Apache running on VM | Run `ss -tlnp \| grep :80` to find the process. Stop it: `systemctl stop apache2` or `systemctl stop nginx` |
| HTTPS shows "certificate not yet valid" | System clock on VM is wrong | `timedatectl status` — if wrong, run `timedatectl set-ntp true` |
| GitHub Actions: "Permission denied (publickey)" | Wrong SSH key in `HETZNER_SSH_KEY` secret | Re-copy the private key: `cat ~/.ssh/hetzner_deploy` — include header/footer lines. Verify the public key matches the key added to Hetzner VM. |
| GitHub Actions: "GHCR login failed" | `GHCR_TOKEN` expired or wrong scopes | Regenerate PAT at GitHub → Settings → Developer settings. Ensure scopes: `write:packages`, `read:packages`. |
| GitHub Actions: build job fails on Dockerfile | Missing build context file | Check `docker build ./api` locally first. Ensure the Dockerfile path in `docker-compose.yml` is correct. |
| Deploy job fails: "image not found" | Build job succeeded but image tag mismatch | Check `needs.build.outputs.image_tag` in workflow. Confirm GHCR packages are public or the VM is logged in to GHCR. |
| Frontend shows blank page after deploy | React build failed silently | Check frontend build logs in GitHub Actions. Run `docker compose logs frontend` on VM. |
| API returns 502 after deploy | API container crashed on startup | `docker compose logs api --tail=50`. Check `.env` for `DATABASE_URL` and `JWT_SECRET` values. |
| `docker compose pull` slow on VM | VM bandwidth limit or GHCR rate limiting | CX32 has 20 TB/month bandwidth. First pull is slow (cache is empty). Subsequent pulls use layer cache — much faster. |
| Paperclip fails to connect to Claude API | `CLAUDE_API_KEY` not set on VM | `docker compose exec paperclip env \| grep ANTHROPIC` — if blank, check `.env` on VM. |
| Disk full on VM | Old Docker images accumulating | `docker system prune -a --volumes` — WARNING: this removes all unused volumes too. Run `docker system df` first. |
| SSL cert expires | Cron job silently failed | `cat /var/log/certbot-renew.log` — check for errors. Verify crontab: `crontab -l`. |
